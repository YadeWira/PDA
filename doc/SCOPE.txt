PDA (packDocument Algorithm) - scope and plan, early development (2026-11-12)
#########################################################################

PDA is the document member of the family. Its job is exactly the "unpack first" step: it opens the
container (ZIP, PDF, OLE2...), undoes every weak compression in a way that can be redone byte for
byte (deflate, LZW, bzip2...), sends each stream to the sibling that handles it best, and rebuilds
the original identically. Same rules as the siblings: byte-for-byte restoration, verify before
writing, store as-is what cannot be taken.

4. Precompression: every compression format that compresses little is recompressed, no exceptions
=================================================================================================

+-------+----------------------------+------------------------------+--------------------------------------+
| Order | Method                     | Where it appears             | How it is rebuilt identically        |
+=======+============================+==============================+======================================+
| 1     | Store (no compression) in  | attachments, embedded        | parse and go down to the files       |
|       | ZIP, 7z, RAR, tar, CAB     | objects                      |                                      |
+-------+----------------------------+------------------------------+--------------------------------------+
| 1     | Deflate / zlib / gzip      | ZIP, OOXML, ODF, EPUB, PDF,  | core engine: try known zlib          |
|       |                            | PNG, WOFF, SVGZ, .gz         | settings, else recipe + differences  |
|       |                            |                              | (preflate-like, written from         |
|       |                            |                              | scratch)                             |
+-------+----------------------------+------------------------------+--------------------------------------+
| 2     | CAB MSZIP                  | .cab, installers             | same deflate engine                  |
+-------+----------------------------+------------------------------+--------------------------------------+
| 2     | LZW                        | PDF LZWDecode, GIF, TIFF,    | PAIA's LZW; parameters in the recipe |
|       |                            | .Z, ARC, ZIP Shrink          |                                      |
+-------+----------------------------+------------------------------+--------------------------------------+
| 2     | bzip2                      | .bz2, .tbz, attachments      | unique BWT; try libbzip2 levels,     |
|       |                            |                              | else recipe                          |
+-------+----------------------------+------------------------------+--------------------------------------+
| 2     | LZ4 / LZ4HC, LZ5 / Lizard, | .lz4, .lz5, .lzo, iWork,     | the stream already is the            |
|       | LZO, Snappy, LZF, LZJB,    | file systems                 | literal/match list: model it; try    |
|       | QuickLZ                    |                              | reference implementations, else      |
|       |                            |                              | recipe                               |
+-------+----------------------------+------------------------------+--------------------------------------+
| 2     | Brotli, low quality (~0-4; | WOFF2, compressed HTML/EPUB, | try the reference implementation per |
|       | cut-off set by measuring)  | .br                          | version and quality, else recipe     |
|       |                            |                              | from the stream commands             |
+-------+----------------------------+------------------------------+--------------------------------------+
| 2     | zstd, low levels           | .zst, modern containers,     | try libzstd per version and level,   |
|       | (fast/negative and ~1-3;   | attachments                  | else recipe from the sequences the   |
|       | cut-off set by measuring)  |                              | frame carries                        |
+-------+----------------------------+------------------------------+--------------------------------------+
| 3     | LZX                        | CHM, LIT, CAB LZX, WIM       | recipe + differences                 |
+-------+----------------------------+------------------------------+--------------------------------------+
| 3     | ZIP Implode / Reduce /     | old ZIPs                     | PKZIP 1.x behaviour, else recipe     |
|       | Shrink                     |                              |                                      |
+-------+----------------------------+------------------------------+--------------------------------------+
| 3     | LHA / LZH (lh0-lh7)        | .lzh, .lha                   | reference implementation, else       |
|       |                            |                              | recipe                               |
+-------+----------------------------+------------------------------+--------------------------------------+
| 3     | ARJ (methods 1-4)          | .arj                         | reference implementation, else       |
|       |                            |                              | recipe                               |
+-------+----------------------------+------------------------------+--------------------------------------+

The rule is about how much a format compresses, not which format it is. Not precompressed (they
already compress well, no margin): LZMA (xz/7z), high zstd levels, high Brotli quality, anything
encrypted. Compressed RAR is out because its encoder is closed and cannot be reproduced (its stored
parts are used).

6. Discarded
============

+--------------------------------------------+---------------------------------------------------------+
| Format                                     | Why                                                     |
+============================================+=========================================================+
| AV1 / AVIF                                 | adaptive multi-symbol arithmetic coder, no known        |
|                                            | recompression                                           |
+--------------------------------------------+---------------------------------------------------------+
| JPEG XL                                    | context-modelled ANS                                    |
+--------------------------------------------+---------------------------------------------------------+
| VP9 / WebM                                 | no known recompression                                  |
+--------------------------------------------+---------------------------------------------------------+
| Encrypted content                          | noise without the key                                   |
+--------------------------------------------+---------------------------------------------------------+
| LZMA (xz/7z), high-level zstd, high        | compress well (little margin) or cannot be rebuilt      |
| Brotli, compressed RAR                     | identically today                                       |
+--------------------------------------------+---------------------------------------------------------+
